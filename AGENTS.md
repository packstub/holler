# packstub/holler

**Holler for Laravel**: the server side of WebRTC calls (1-on-1 and groups up to `max_participants`, 4 by default) between the users of a Laravel app. Laravel only does signaling (who calls whom; offer, answer, ICE candidates, reset and state relayed through a table) over polled HTTP, no websockets, no media. Free, MIT. `packstub/filament-holler` (the sibling repo, `plugins/filament-holler`) puts it into a Filament panel and requires this package; the browser engine is `@packstub/holler` (`plugins/holler-js`). `filament-holler` lives in `Packstub\FilamentHoller\`, this package in `Packstub\Holler\` (one PSR-4 root per package). Split out of `filament-holler` on 2026-10-23; private repo, untagged.

## Commands

```bash
composer test               # Pest suite (Testbench, in-memory SQLite, no Filament, no Livewire)
composer test:filter <name>
composer lint               # Pint
composer test:browser       # Pest browser tests: the plain widget in Chromium, two or three people signed in (npm install, npx playwright install chromium once)
```

Browser tests are slow (tens of seconds to minutes): run them once before a release or after a change to the widget's behaviour, not after every edit. The Pest and Vitest suites cover the logic.


## Layout

- `src/Holler.php` + `Facades\Holler`: the service. `routes(prefix, middleware, as, window)` registers the twelve JSON routes and the pop-out page (`window: false` leaves it out). Keep the `@method` list on the facade in step with the public methods. `start()` (one callee or a list), `invite()`, `hold()` / `resume()` (the participant status `on_hold`: still on the call, no window, no signals; one per person, a resume puts the call I am in on hold instead; `hold_timeout` after the holder's last poll drops them), `people()` (the search behind Add someone: the context's `searchUsers()` asked for up to `SEARCH_CANDIDATES` matches and read lazily, then `canCall()` and the call's roster, stopping at the first 8 it may show), `answer()`, `decline()`, `hangup()`, `withdraw()` (a participant is gone; the call ends once fewer than two people or nobody joined are left), `end()`, `signal()` (to one participant or to every other live one), `expire()` (missed and dropped per participant), `poll()`, `openCallsOf()`, `present()` are the whole signaling logic; `store`, `invite` and `people` sit behind the rate limiters `holler-calls` and `holler-people` (`rate_limits` in the config, per scope and user, registered in the provider; 0 turns one off), whatever middleware the caller passes. `CallsController` only validates, resolves the participant (401/403) and maps `CallException` → `HttpException` with the exception's `status`. Macroable, so the Filament package can add panel helpers.
- `src/Contracts/CallContext.php`: what differs between a plain app and a panel (`scope`, `currentUserId`, `findUser`, `who`, `canCall`, `searchUsers`, `iceServers`, `hasVideo`, `maxParticipants`). `src/AppContext.php` is the plain-Laravel implementation: config keys plus fluent closures. The provider binds it only when nothing else is bound, so the Filament package's `PanelContext` wins whatever the provider order.
- ICE servers: `Holler::iceServers()` is what the `ice` route returns, the context's list normalised (several URLs in one string split on commas, a server without a URL dropped, a server with `secret` signed by `turnCredentials()`: coturn's `use-auth-secret`, username `<expiry>:<user id>`, HMAC-SHA1 in base64; the secret never leaves the server). `config('holler.ice_servers')` stays the raw list (`HOLLER_STUN_URL`, `HOLLER_TURN_URL`, `HOLLER_TURN_SECRET`, `HOLLER_TURN_TTL`, or the fixed username and credential).
- `src/Exceptions`: `CallException` (abstract, `status`) → `CallNotAllowed` 422, `CallFull` 422, `CalleeBusy` 409, `CallNotRinging` 409, `CallHasEnded` 410, `SignalTooLarge` 413, `TooManySignals` 429 (`max_pending_signals` unread from one sender); each has a `reason` word the controller returns beside `message`.
- `src/Participant.php`: a guest made in code (`guest:<uuid>`, name, avatar stored on the participant row); ids with a colon are never looked up. Calls carry `kind` (`call` for the widgets) and `scope` (the context's guard; `openCallsOf()` and the routes filter on it, guests excepted). State changes (`answer`, `withdraw`, `end`, `invite`) run in `transaction()` on the configured connection and `lock()` the call row, re-reading it first. `holler:prune` (`src/Commands/PruneCommand.php`).
- `src/Models/Call.php` (`ringing | active | ended`, `end_reason`, `caller_id`, `callee_id` = the first person called, `participants`, `participant()`, `live()`, `peersOf()`, `peerOf()` = the first live other for the 1-on-1 fields, `duration()`, `end()` deletes the signals, and a claiming poll deletes the ones up to its cursor; `CLAIM_SECONDS` = 5), `src/Models/CallParticipant.php` (`seat` in invitation order, the caller at 0; `ringing | joined | on_hold | left | declined | missed | dropped`, the first three `LIVE`; `tab` / `seen_at` for the window that claimed the side, `claim()` is one atomic UPDATE, `release()`, `isClaimed()`), `src/Models/CallSignal.php` (`from_user_id`, `to_user_id`, `offer | answer | ice | reset | state`).
- `src/Events/{CallStarted,CallAnswered,ParticipantJoined,ParticipantHeld,ParticipantResumed,ParticipantLeft,CallEnded}.php`, `config/holler.php` (`HOLLER_*` env), `resources/lang/{en,de,ro,ru}/messages.php` (`holler::messages.*`: server-side messages) and `ui.php` (the widget's labels; the same keys in every language, a test checks), `database/migrations/create_holler_tables.php` (`holler_calls`, `holler_call_participants`, `holler_call_signals`; loaded by the package, `runsMigrations()`).
- `HollerServiceProvider::packageBooted()` skips `TrimStrings` and `ConvertEmptyStringsToNull` for `*calls/*/signals` (an SDP ends in CRLF and the parser wants it there; Firefox sends `candidate: ""` last): a custom route prefix must end in `calls` or register its own skip.
- Tests: `tests/TestCase.php` registers `Holler::routes()` under `web` (so `auth` and sessions work as in an app); `CallsTest` (the endpoints as two users), `GroupCallsTest` (three and four people: seats, addressed signals, decline/leave/invite, the cap, missed and dropped participants; `keepPolling()` moves time while people poll, since a participant quiet past the timeout is dropped whoever triggers `expire()`), `ReconnectTest` (tabs, hold, leave, reclaim, timeouts), `HoldTest` (a call on hold: hold, resume as a swap, busy, the hold timeout), `PeopleTest` (the `people` route), `ContextTest` (AppContext, the service without HTTP, exceptions, custom prefix, guard). Timing tests `freezeSecond()` first: seen-at times are stored to the second.

## Conventions

- PHP 8.3+, Laravel 12 and 13. Every change needs a Pest test and a `CHANGELOG.md` line; the tag is `v<version>` on `main`, the release workflow takes the notes from the tag's section. Keep the section short and human, since the workflow appends GitHub's list of merged pull requests under it: an optional lead sentence, then at most about six one-line bullets saying what a user gets, in plain words (class or method names only when a user needs the name, never lists of them). Always keep breaking changes with an `**Upgrading:**` line, security or privacy fixes, new minimum versions and migrations to run; CI, tests and refactors stay out.
- Nothing here may import from `Filament\` or `Livewire\`; what needs a panel belongs in `packstub/filament-holler`.
- User ids are strings everywhere (`caller_id`, `callee_id`, `user_id`, `from_user_id`, `to_user_id`, the JSON), so integer and UUID keys both work.
- The route names (`{as}poll`…), the JSON shapes of `present()` and `poll()`, the signal types and the `CallContext` methods are shared with `filament-holler` and `@packstub/holler` (its `FakeServer` mirrors the rules); they must not change inside a major. Schema changes follow the workspace rule (final shape in `create_*`, guarded `add_*`); the 2026-10-28 move to participants and the 2026-11-12 `holler_` prefix on the three tables edited the create migration in place because nothing was tagged or installed yet.
- Authorization stays in the service (`start()` asks the context), never only in a controller.
- After a change here run the Filament package's suite too (`plugins/filament-holler`, `composer test`).

## The widget

`resources/dist/` holds the engine (`index.js`), the widget (`widget.js`) and its stylesheet (`widget.css`), the minified build of `@packstub/holler` (its `dist/`, made by esbuild there; the readable source and the tests live in `plugins/holler-js`), copied by `npm run build:js` (from `node_modules`) or `npm run build:js:local` (builds the checkout `../holler-js` first, the way to pick up uncommitted engine work) and committed, so Composer users need no npm. Never edit these files here. `AssetController` serves them (`Holler::asset()` adds a version), `<x-holler::widget />` (`resources/views/components/widget.blade.php`) builds the `CallWidget` config and `<x-holler::button />` renders a `data-holler-call` button; the pop-out page is `PopOutController` + `holler::window` (the name `WindowController` is taken by `filament-holler`, in its own namespace since 2026-10-28). The labels in `lang/en/ui.php` mirror `labels` in `widget.js`; keep the two lists the same.
