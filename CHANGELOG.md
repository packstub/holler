# Changelog

All notable changes to `packstub/calls` are documented in this file.

## Unreleased

First release. The signaling core moved here from `packstub/filament-calls`, which now requires this package and adds the panel UI.

- `Calls::routes()` registers the eight JSON signaling routes (`poll`, `store`, `answer`, `decline`, `hangup`, `invite`, `signals`, `leave`) under a prefix, name and middleware of your choice.
- `Calls` service and facade: `start()` (cancels the caller's open call first, refuses yourself, nobody or anyone the context says no to, 409 when the callee is busy), `answer()`, `decline()`, `hangup()`, `end()` (idempotent, deletes the signals, fires `CallEnded` once), `signal()`, `expire()` (missed past `ring_timeout`, dropped past `reconnect_timeout`), `poll()` (the one request every window repeats: claims a side with `hold`, signals only to the holder, an id cursor), `present()`; typed `CallException`s with the HTTP status the endpoints answer with.
- `CallContext` contract: who is signed in, how to find and name people, who may call whom, ICE servers and whether calls start with video. `AppContext` for a plain Laravel app: the `packstub-calls` config file plus `canCallUsing()`, `userNameUsing()`, `userAvatarUsing()`, `iceServersUsing()` and `video()`; bound only when nothing else is bound so a panel package can take over.
- Reconnecting: each window holds its side of a call (`tab` and `seen_at` on the participant, from polling), a `leave` beacon frees it on unload, a new page claims it and starts after the signals meant for the old connection.
- `calls`, `call_participants` and `call_signals` tables; `Call` model with `duration()`, `participants`, `live()`, `peersOf()`; `CallParticipant` with `claim()`, `release()`, `isHeld()`; `CallSignal`; `CallStarted`, `CallAnswered`, `CallEnded` events.
- Signal types: `offer`, `answer`, `ice`, `reset` and `state` (a side tells the other that it muted, turned the camera off or shares the screen; the payload is the client's).
- `TrimStrings` is skipped on the signals route so a session description keeps its trailing CRLF.
- Config `packstub-calls.php` with `CALLS_*` env variables: STUN and TURN, poll intervals, ring and reconnect timeouts, video, guard.
- Group calls (up to `max_participants`, 4 by default, `CALLS_MAX_PARTICIPANTS`; `AppContext::maxParticipantsUsing()`, `CallContext::maxParticipants()`): a `call_participants` table with a row per person (seat in invitation order, the caller at 0; status `ringing`, `joined`, `left`, `declined`, `missed` or `dropped`; the window that holds the side and its heartbeat), in place of the per-side columns on `calls`. `POST calls {callees: [...]}` rings several people at once, `POST calls/{id}/invite {callee}` adds someone to a running call (`Calls::invite()`, a `CallFull` exception at 422). Someone who hangs up leaves the call for the others; it ends once fewer than two people, or nobody who joined, are left. An invitee rung past `ring_timeout` is marked missed and a participant quiet past `reconnect_timeout` dropped, without ending a call that still has two people on it. The seat of someone added to a call is taken under a lock on the call, so two invites at once never share one.
- The call UI for a plain Laravel app: `<x-calls::widget />` in a layout and `<x-calls::button :user="$user" />` wherever there is someone to call. The widget (`CallWidget` from `@packstub/calls`, no framework) draws the incoming toast, the call window with a tile per person, mute, camera, screen share and hang up, a chip while the call runs in its pop-out window (`GET {prefix}/window`, `CALLS_POP_OUT` to keep calls in the page), and notices. Its stylesheet and modules are served by the package (`GET packstub-calls/assets/{file}`, `Calls::asset()`, versioned and cached), so there is nothing to publish or bundle; the texts are in `lang/en/ui.php`. Restyle it through `--calls-*` custom properties, replace any view's markup with a template of your own, or listen to `calls:*` events on the page.
- `Calls::whoAre()` names a whole roster in one query: `AppContext::findUsers()` (and `AppContext::retrieveMany()` for any user provider; one query on an Eloquent provider) is used by `present()` when the bound context offers it, else people are looked up one by one.
- Signals carry `from` and can be addressed: `POST calls/{id}/signals {type, payload, to}` queues one copy for that participant, without `to` one for every other live participant (`Calls::signal()` returns the last written, null when nobody is left to receive it).
- The call JSON gains `seat`, `joined` (false while the call rings me) and `peers` (everyone else: id, name, avatar, seat, status, held, seen_ago); `peer`, `peer_held` and `peer_seen_ago` stay, for the first live peer, so a 1-on-1 client keeps working.
- `ParticipantJoined` and `ParticipantLeft` events (the latter with the participant's status); `CallAnswered` fires once, when the first person joins.
